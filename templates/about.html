About JobShield AI

How the project works, what the numbers mean, and — just as importantly — what it cannot do.

The problem

Fraudulent job adverts are cheap to create and hard to spot. They often promise high pay for little work, ask for a "registration" or "training" fee, or request identity documents before any interview. Job seekers usually have minutes, not hours, to decide whether to reply.

JobShield AI gives you two independent second opinions before you commit: a machine-learning estimate based on how the advert is worded, and a transparent list of warning signs based on rules a person can read and check.

The machine-learning pipeline

  1. Collect the data. We use a public, labelled dataset of real job postings (EMSCAD), where every posting is marked either fraudulent or genuine.
  2. Clean it up. Missing text becomes an empty string, and duplicate postings are removed before the data is split, so the same advert cannot appear in both the training and the test data.
  3. Split it. The postings are divided into a training set and a held-out test set. The test set is locked away and only used once, at the very end.
  4. Turn words into numbers (TF-IDF). See the explanation below.
  5. Train a classifier. Logistic Regression learns which word patterns tend to appear in fraudulent postings.
  6. Test it once. The locked-away test set measures how well it really does on adverts it has never seen.

What TF-IDF does, in plain language

A computer cannot read words, so each posting is turned into a long list of numbers. TF-IDF gives every word a weight: term frequency rewards words that appear often in this posting, and inverse document frequency discounts words that appear in almost every posting (such as "the" or "job"). The result is that distinctive wording — like "registration fee" or "no interview" — carries more weight than everyday filler. Word pairs (bigrams) are included too, so "no interview" counts as one clue rather than two unrelated words.

Why Logistic Regression

Logistic Regression draws a straight-line boundary between "looks genuine" and "looks fraudulent" in that huge space of numbers, and it gives a score between 0 and 1. It trains in seconds on a laptop, it is easy to explain, and its coefficients can be read back as "which words pushed the decision this way". That transparency is exactly what a project about explainability needs. It is a baseline, not the last word — the docs list stronger models as future work.

Why the vectorizer is fitted on the training data only

If the word weights were calculated using the test set as well, the model would effectively have peeked at the answers, and the reported scores would be flattering and untrue. Fitting TF-IDF only on training data keeps the test set an honest measure.

Handling the imbalance

Fraudulent postings are a small minority of the dataset. A lazy model could score well simply by saying "genuine" every time, which would be useless. We therefore train with balanced class weights and choose a decision threshold from cross-validated training predictions, so the model is encouraged to catch fraud while we still report how many false alarms it raises.

The warning-sign engine

Running separately from the model is a set of readable rules — for example "asks for a registration fee" or "asks for an Aadhaar or PAN copy before any interview". Each rule has a severity, an explanation of why it matters, and a suggested next step. The rules are deliberately kept apart from the model: the two are shown side by side, and they are never added up to produce a single "scam score".

A rule firing is a prompt to look closer. It is never evidence that a scam has occurred, and the absence of warning signs never means a posting is safe.

Limitations

  • The model learns from past adverts. Scams change, and wording that is new to the model will not be recognised.
  • A genuine-but-unusually-worded advert can look suspicious, and a well-written scam can look normal. The tool makes mistakes in both directions.
  • The dataset under-represents non-English postings, so results for those are less reliable.
  • Nothing here verifies a company. There is no registry lookup, no business database and no link-reputation service connected to this project.
  • History is tied to a cookie on your browser. Clearing your browser data removes access to your saved analyses.

Responsible use

Treat the output as one input among several. Check the company's official careers page, look the organisation up independently, and speak to a real person before sharing anything sensitive. Never pay money to get a job.
